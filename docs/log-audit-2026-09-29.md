## Bug 清单与证据

### BUG-1（主诉）：手动 ⌃Q 摆位的窗口被「提交归位」链自动拽回副屏
- **量级**：UPS 触发的拽回 4 天 43 次（09-25:3、09-26:3、09-27:26、09-28:11）。
- **机制**：⌃Q/Stop 把窗拉到主屏时保存 ToggleRecord（原位=副屏）→ 用户提交
  prompt → UserPromptSubmit hook → 65a1ad2（09-16）定案「有记录即归位，不论来源」
  → ToggleEngine.restore 拽回副屏。
- **铁证**：
  - 09-28 13:47:48 窗 8756 `reason=manual_hotkey` 拉上主屏，13:47:51（3.3s 后）
    提交即被拽回；
  - 09-28 15:12:49→15:16:02 窗 8760 连续两轮「拉回→提交→被拽」；
  - 09-27 单日 26 次。
- **历史脉络**：B126（09-11）为此症状加 userPlacedSkip → 09-15 用户报反方向
  （关气泡后回车不归位，实为「同一手动放置窗口气泡归位/回车不归位」的分叉）→
  65a1ad2（09-16）退役守卫 → 症状回归。本次修订以「**一致跳过**」满足 09-15 的
  一致性诉求：手动摆位粘滞，气泡提交与直接回车都不 Undo 用户放置；⌃Q 再按一次
  仍可手动还原。
- **修复**：`AutoRestoreRecordGate`（Sources/Toggle/AutoRestoreRecordGate.swift）+
  UPS 决策表新分支 `.manualPlacementSticky`（响应码 `manual_placement_stays`）+
  气泡提交门同源接入门判定（InputBubbleController+Submission）。

### BUG-2：陈旧 toggle 记录无时效，几小时前的凭证仍驱动拽回
- **铁证**：09-28 12:35:35 无绑定会话 self-heal 绑到聚焦窗 8652 → 一份不知几小时前
  的记录立即触发拽回。`decidePromptMove` 只看记录存在性，`ToggleRecord.toggledAt`
  从未被消费。
- **修复**：记录 30 分钟时效窗（`AutoRestoreRecordGate.maxRecordAgeSeconds`），
  超龄 → `.recordExpired`（响应码 `toggle_record_expired`）不归位；⌃Q 手动还原
  不受时效影响。正常 Stop→读结果→提交的分钟级节奏不受影响。

### BUG-3：窗口已在原位仍跑全量 restore 管线（6 秒 focus 扫射 + 视图带跳）
- **铁证**（traceID=ups-00144628，09-28 12:35:35-46）：窗 8652 已在原帧（记录陈旧），
  restore 仍执行：源屏预切回 → `refocusWindowOnSpace` 逐个 focus **6 个候选窗**
  （含无辜的 8756，每次 fork 最长 755ms）→ 全败（6056ms）→ move/resize "could not
  locate" → 期间 macOS 把用户视图自动带跳空间（postSpace=3 preSpace=2）。
- **修复**：①资格门加「已在原位」短路（`.alreadyAtOriginal`，帧收敛容差内判等，
  陈旧记录直接清理，响应码 `already_at_original`，零移动零 focus）；②
  `refocusWindowOnSpace` 候选尝试上限 `refocusMaxCandidates = 2`（前 2 个带不动
  即如实放弃，不再逐窗扫射抢焦点）。

### BUG-4：气泡/UPS 双通道重复归位（同一条记录被消费两遍）
- **证据**：09-28 当天 `input_bubble_submit` restore 42 次、`hook_user_prompt_submit`
  restore 19 次，同一次提交两通道竞速（B176「UPS 晚 2s 到见无记录」的假设实测
  不总成立，UPS 常更快到达 → 两条全量管线背靠背执行，含两遍视角守卫 focus 链）。
- **修复**：`RestoreInFlightRegistry`（Sources/Support/，8s 新鲜期）——双方决策点
  （均在主线程）先查后占，后到者诚实跳过（UPS 响应码 `restore_already_active`；
  气泡侧日志 skip 保留决策上下文）。

### BUG-5：RemoteSpoolDrainer 对不可达主机无限空转
- **量级**：`cc11001100@192.168.1.90` 自 09-25 起持续 `drain failed (timeout/spawn)`，
  四天 **17,122 次**失败（2s 轮询 × 10s ssh 超时 + 8s mux 重置 ≈ 每 12-20s 一轮），
  同期 .83 正常（170 次成功）。白耗 fork/网络，日志噪音，恢复后积压会突发投递
  （=「没提交任何东西窗口自己动」的潜在来源）。
- **修复**：指数退避（`RemoteSpoolDrainLogic.backoffDelay`：streak n →
  min(10s·2^(n-1), 600s)），`HostStatus.failureStreak/nextAttemptAt` 落账，tick 按
  到期过滤；设置页「立即拉取」force 旁路退避。稳态不可达主机从 ~720 次/天收敛到
  144 次/天。

## 语义裁决记录（本次取的口径）

「提交归位」资格 = **自动化来源（Stop 拉回 / 命令 API）且记录 30min 内且窗口不在
原位**。手动 ⌃Q 摆位粘滞（任何自动链不 Undo）；超龄记录不归位但 ⌃Q 手动还原
不受影响；「UPS 永不搬窗」（09-11 红线）不动。气泡提交与直接回车共用同一资格门
（09-15 的一致性诉求以「一致跳过」保留）。若使用体感需要再调（时效窗时长/是否
做成偏好），在设置页「提交后自动恢复」开关之外另立偏好即可，决策表已按可注入
纯函数收敛。

## 第六轮：0.0.93 当晚再被否 → 0.0.94 终局=提交瞬间归位（fix/submit-restore-instant）

**用户裁决（0.0.93 装机后）**：「提交后为什么还在等 3 秒呢？不能马上吗？等 3 秒会

## 第九轮：⌃Q 两处断裂（AX 判据洞 + 焦点守卫误拽）→ 0.0.98
